---
name: Imported project with pre-existing artifact.toml
description: What to do when a GitHub-imported repo already has artifacts/*/.replit-artifact/artifact.toml files but listArtifacts() returns empty and no workflows exist.
---

A project can be re-imported from GitHub with fully-formed `artifacts/<slug>/.replit-artifact/artifact.toml`
files already committed (from a prior Replit session), yet the platform's artifact registry has no record
of them: `listArtifacts()` returns `[]` and `listWorkflows()` returns `[]`, even though the `.replit` file
itself was freshly regenerated by the importer (it only has generic `[workflows]`/`[agent]`/`[nix]` sections,
no service entries).

**Why:** artifact registration lives in platform state keyed by artifact ID, separate from the files in git.
Re-importing a repo brings back the files but not that registration state.

**How to apply:** Do not try to fix this by calling `createArtifact()` with the same slug — it fails fast with
`ARTIFACT_DIR_EXISTS` and does not adopt the existing directory (confirmed safe/non-destructive, but a dead end).
There is no documented "adopt existing artifact" callback. The practical workaround: register plain workflows
with `configureWorkflow` that `cd` into each `artifacts/<slug>` directory and run its dev command, passing
`PORT`/`BASE_PATH` (and any other required env vars declared in `artifact.toml`'s `[services.env]` /
`[[services]]` blocks) inline in the shell command, e.g.
`cd artifacts/thesis-mgmt && PORT=21277 BASE_PATH=/ pnpm run dev`.

Consequences of this workaround worth telling the user/future agent:
- The app IS reachable at the dev domain root/paths and works normally.
- It will NOT show up in `listArtifacts()`, the artifact preview dropdown, or `Screenshot`'s `appPreview`
  source (`Artifact not found`). Use `Screenshot` with `externalUrl` + the `$REPLIT_DEV_DOMAIN` URL instead.
- Production/publish flow for these services may need separate verification since they were never registered
  through the normal `createArtifact` path — flag this to the user before they publish.
